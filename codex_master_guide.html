Quick Start for New Codex Users

Use these three steps when you open a project and want Codex to help safely.

Step 1 Open the project in VS Code

Start from the folder that contains the files you want Codex to edit.

Step 2 Open the VS Code terminal

Run pwd and git status before starting work.

Step 3 Start Codex from that folder

Run codex, then ask it to read memory and inspect the project first.

Foundation

1. Big Picture

Codex works best when it starts inside the correct project folder and knows the project history.

VS Code Your editor. Open the project folder here so you can see files and changes.
Terminal The command window. Use it to move folders, start Codex, and run Git commands.
Codex Your coding assistant. Start it from the project folder so it can read and edit the right files.
Project Memory A short note file that tells Codex important facts about each repo or project.
Simple rule: open the project folder first, then start Codex from that folder.

Why VS Code is better than terminal alone

VS Code gives Codex a better workspace because the project files, terminal, source control, search, and editor are all visible together.

Instead of switching between a standalone terminal and separate file windows, you can ask Codex to make changes, review the exact files, run commands, check Git status, and continue editing in the same project window.

  • You can see and edit files immediately.
  • The integrated terminal stays inside the project workspace.
  • Git changes are easier to review before commit or push.
  • Project folders are clearer for beginners.
  • Codex instructions, memory files, and commands are easier to manage.
  • You do less context switching than with terminal alone.
Mac setup

2. How to Start Codex in a New VS Code Terminal

Use this when you are already inside VS Code and want Codex to work on the open project.

Open the project folder in VS Code

In Terminal, go to the project folder and open it:

cd ~/codex/study_plan/git_repo/study-dashboard
code .
Open a new Terminal inside VS Code

Use the menu: Terminal > New Terminal

Shortcut on Mac:

Control + `
Check that Terminal is in the project folder 
pwd
ls
Start Codex 
codex
If `pwd` shows the project folder before you run `codex`, Codex is starting in the right place.

What integrated terminal means on Mac

The VS Code integrated terminal is the terminal panel that opens inside VS Code, usually at the bottom of the window. On Mac, it normally uses the default Mac shell, which is zsh.

You can check your shell with:

echo $SHELL

If the result is this, your setup is correct:

/bin/zsh
Your current Mac VS Code terminal uses /bin/zsh, so you are already using the recommended setup.
Platforms

3. Mac vs Windows Platform Differences

VS Code looks mostly the same on Mac and Windows. The biggest difference is the terminal underneath VS Code.

Mac Mac is Unix-like and usually uses zsh. Many developer commands work naturally. 
cd ~/codex/repo_name
ls
pwd
codex
Windows Windows may use PowerShell, Command Prompt, Git Bash, or WSL. The commands can change depending on the terminal. 
cd C:\Users\YourName\codex\repo_name
dir
Get-Location

Best beginner recommendation

  • On Mac, use VS Code with the integrated terminal running zsh.
  • On Windows, use VS Code with WSL Ubuntu when possible.
  • If WSL is not available, Git Bash is usually easier for Codex examples than Command Prompt.

Why WSL helps on Windows

WSL gives Windows a Linux-style terminal. That makes many Codex instructions easier to follow because commands such as ls, cd, pwd, git, npm, and python behave more like they do on Mac and Linux.

Area Mac Windows
Default shell zsh PowerShell or Command Prompt
Recommended shell zsh WSL Ubuntu
Path style /Users/name/project C:\Users\name\project or /home/name/project in WSL
List files ls dir in PowerShell, ls in WSL
Environment variable example $HOME $env:USERPROFILE in PowerShell
Scripts .sh scripts work naturally Best inside WSL or Git Bash
Simple summary: VS Code is similar on both platforms, but terminal commands can differ. Mac is already Unix-like. Windows is closest to Mac/Linux when using WSL.

Memory

5. How to Create Memory for Each Repo or Project

A memory file is a plain text Markdown file. Keep one memory file per important project.

Where memory files live

~/.codex/memories/

Create a memory folder if it does not exist

mkdir -p ~/.codex/memories

Create or open one memory file per project

code ~/.codex/memories/study-dashboard.md
code ~/.codex/memories/codex-guide.md
code ~/.codex/memories/my-new-project.md
Use a simple filename that matches the repo name. Example: repo `study-dashboard` uses memory file `study-dashboard.md`.

What to save in project memory

  • Project path on your Mac
  • GitHub remote URL
  • Main files and folders
  • How to run or test the project
  • Important passwords, PIN behavior, or config notes only if they are safe to store locally
  • Recent changes Codex should remember
  • Special warnings, such as service worker cache or browser compatibility

Ask Codex to update memory

Update this project memory after the work is complete:

~/.codex/memories/study-dashboard.md

Include:
- Project path
- Files changed
- New workflow notes
- Validation command
- Any warnings for future Codex sessions
Template

6. Copy This Project Memory Template

Paste this into a new memory file, then fill in the blanks.

# Project Name Memory

- Project path: `/full/path/to/project`.
- GitHub remote: `https://github.com/OWNER/REPO.git`.
- Current main branch: `main`.
- Project type: static HTML, React app, Node app, Python app, or other.
- Main entry file: `index.html`.
- Main CSS file: `css/style.css`.
- Main JavaScript file: `js/app.js`.
- Validation command: `npm test`, `node tools/validate-project.mjs`, or manual browser test.
- Local run command: `python3 -m http.server 8000`, `npm run dev`, or other.

## Important Workflow

- Start from the project folder before running Codex.
- Check `git status` before edits.
- Use a branch before large changes.
- Do not change unrelated files.

## Recent Notes

- Add short notes here after each important update.
- Include links, routes, PIN rules, deployment notes, and known problems.

Git

8. Git Workflow for Beginners

Git saves versions of your project. GitHub stores the project online.

Check status

git status

See what changed

git diff

Create a work branch for changes

git switch -c docs/update-guide

Save your work

git add .
git commit -m "Update guide"
git push -u origin docs/update-guide

When working directly on main

git add .
git commit -m "Update website"
git push origin main
Be careful with commands that discard changes, such as `git reset --hard` or `git checkout -- .`. Ask Codex to explain the risk before using them.

Recovery

12. Recovery Commands

Use recovery commands only after checking what changed.

View changed files

git status
git diff

Restore one file

git restore path/to/file.html

Undo the last commit but keep the file changes

git reset --soft HEAD~1

View commit history

git log --oneline
Avoid `git reset --hard` unless you truly want to delete uncommitted work.
Codex

13. Useful Codex Commands and Prompts

Use these when working inside Codex so the session stays clear and efficient.

Type Use Example
Start Codex Launch Codex from the current project folder. codex
Compact session Reduce token usage while keeping the important context. /compact
Read memory Tell Codex to load the saved project notes before work starts. read memory
Update memory Tell Codex to save the latest project state after changes. update memory
Project scan Ask Codex to inspect the codebase before making edits. read memory and inspect the project first
Safe edit request Ask for a focused code change with validation. apply the change and run tests
Status request Ask Codex for the current repo, branch, and changed files. status
Only codex and /compact are direct commands here. The others are short prompts that work well in normal Codex chat.
Tokens

14. Use Compact to Save Tokens

Use compact when the Codex conversation is long and you want to reduce token usage while keeping the important context.

Simple command

/compact

Better prompt before starting a new task

Compact this conversation and keep:
- Current project path
- Current branch
- Files changed
- User requirements
- Validation results
- Important project memory notes
- Next steps

When to compact

  • After a feature or fix is completed
  • Before starting a new unrelated task
  • After Codex has read many files
  • When the conversation is long and token usage is high
Compact is for conversation context. For permanent project facts, save them in a memory file under `~/.codex/memories/`.
